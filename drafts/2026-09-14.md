Fact check:
- Two rule-outs tested in the wrong regime, and unscoped negatives nearly killed the winning direction: failure mode 5, `docs/superpowers/specs/2026-07-25-chi-v1-design.md:30`. A human epistemic reset reversed them (the STEERING.md reset, `:39`). The spec lists both under the same failure mode. The post treats them as the same pair.
- "A dead-ends list stops agents retrying failed ideas": spec `:18`. The ledger "genuinely stopped re-exploration — for agents that obeyed it."
- "won't record a dead end without evidence": both write paths reject empty evidence. `chi deadend` prints `REJECTED` and exits 1 (`chi/cli.py:307-311`). The litellm `report_deadend` handler returns `REJECTED` (`chi/agents/litellm_loop.py:185-191`). The column is `evidence_json TEXT NOT NULL` (`chi/store/schema.sql:64`).
- "agents can challenge one": `chi challenge --neg-id --hypothesis` (`chi/cli.py:320-330`) flips the entry to `challenged` (`chi/store/ledger.py:170-183`). The steering digest points agents at it (`chi/orchestrator/steering.py:65-66`). Only CLI-driven agents can run it, since the litellm loop has no challenge tool. That's why it says "agents" and not "any agent".
- Self-reply, "drops out of what agents get seeded with": that's `list_negatives(status="active")` feeding the seed context (`chi/agents/context.py:24`) and the steering digest (`steering.py:54`). The director's own DEAD list still counts a challenged class, because `dead_classes` counts any status (`ledger.py:86-91`). So the reply says "seeded with", not "removed". The URL resolves: `chi/store/ledger.py` is on `origin/main` (`git ls-tree`).
- Deliberately not claimed: that chi requires scope. It doesn't. `chi deadend --scope` defaults to `""` (`cli.py:305`), and the litellm `report_deadend` tool has no scope field at all (`litellm_loop.py:37-41`, handler `:192-195`). The post only says unscoped negatives did damage. If someone replies "so do you require scope?", the honest answer today is no. That's flagged as a background task, "Require scope on dead-end ledger entries".
- The angle bank's "hard-blocked" is also left out. It's a label in the director's steering text, `(repeated — hard block)`, on classes ruled out 2+ times (`chi/director/strategy.py:39`). A repeated dead class also classifies the round STUCK (`review.py:66`). No code stops an agent from trying one.
